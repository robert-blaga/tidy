# When nothing fits

The fallback. Read this when no approved skill in the `index.md` makes sense for the user's input.

If a skill DOES cover the user's input, do NOT use this fallback — read the skill and follow it.

## Be curious

You don't know what the user wants yet. Don't pattern-match prematurely. The input could be anything, and the right response could be anything. Investigate before proposing.

## The loop

1. Look at the input. Use whatever tools fit to understand what it is.
2. Look at the user's setup. Read-only. What's the context — how do they organize, what have they taught you, what shape does this fit?
3. Form a hypothesis about what action would be best taken — what you think the user wants from this. Offer it as a hypothesis, not an assertion. Lead with one concrete idea, not a menu.
4. Tell the user. Lay out your hypothesis with the evidence you found. Then propose the skill this batch would teach: what kind of input it would match, what it would do, how it would handle the situation next time. The user can agree, redirect, or clarify.
5. On approval, act on the action and write the skill. Log the batch per `how-to-log.md` regardless of outcome. See `how-to-update-the-wiki.md` for skill format and naming.

## Be honest about missing tools

If you need a tool that isn't installed, say so plainly and offer the install. Don't pretend you can do the work without it.
